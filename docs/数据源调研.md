# 数据源调研（旅游费用查询网站）

- 调研日期：2026-10-18（页面价格均为当日页面所示）
- 调研人：data-scout（实测型调研，全部结论附实测 URL 与页面特征）
- 边界：本文件只做调研文档，未改动 server/、web/、数据库与其它 docs
- 口径前提：本站展示的是**参考价**（帮用户估一趟花多少钱），不是实时报价下单

---

## 0. 一句话结论

**景点门票、火车票价、城市清单三类可以合规自动化抓取（已实测拿到真实价格）；酒店价格在所有主流平台都锁在“登录后可见”的墙后，只能做“参考价区间 + 后台批量导入”；机票只能给区间。**

---

## 1. 结论摘要（能抓什么 / 抓不到什么 / 建议口径）

| 数据类 | 判定 | 能自动抓的来源 | 抓不到 / 只能参考价的原因 | 建议入库口径 |
| --- | --- | --- | --- | --- |
| 城市清单 | ✅ 可自动抓 | 民政部《2023 年中华人民共和国行政区划代码》（省份权威）；携程酒店页脚「热门城市」40 个（热度信号） | 没有官方“热门旅游城市”红头名单；“热门”是平台口径，只能当参考标签 | 直接入库 78 个城市（37 热门 + 41 潜力），省份取民政部 |
| 景点门票 | ✅ 可自动抓（主力） | 携程攻略景点列表 `you.ctrip.com/sightlist/<城市><id>.html`（未登录，静态 HTML，含“门票 ¥210 起 / 原价 ¥220 / 免费”） | 少数 5A（故宫、天坛、颐和园）在列表中不给价，需景区官网补；官网价分淡旺季 | `ticket_price` 存“起价”，另用 note 存“原价/淡旺季”，note 里写来源 |
| 酒店价格 | ❌ 抓不到（只能参考价） | 无。携程/去哪儿/美团/飞猪全部锁价（详见 §2.2） | 携程“登录以查看会员价”“登录看低价”；去哪儿跳回首页；美团/同程 403；飞猪跳淘宝登录；Trip.com 国际站能读到价但 robots.txt 明令禁止 | 只做**参考价区间**（如“¥150–250/晚”），由管理员后台 CSV 批量导入或人工整理；页面标注“参考价，实际以平台为准” |
| 酒店名称/地址/评分 | ⚠️ 半自动 | 高德开放平台 POI 搜索（需申请 key，有免费额度，合法 API） | 携程自家列表页 robots 禁止抓取，不能当生产数据源 | 用高德 POI 拉名单，价格另配参考价 |
| 火车票价 | ✅ 可自动抓 | 携程火车票静态 SEO 页 `trains.ctrip.com/trainbooking/<拼音>-<拼音>`（未登录，含车次+时刻+时长+各席别票价） | 12306 官方查询接口要 cookie/滑块，抓不了；携程页“余票”需登录（但票价是静态文本） | `transports` 存二等座最低价 + 最短耗时，note 写车次与查询日期 |
| 飞机票价 | ❌ 只能给区间 | 无稳定公开源（携程机票列表页未登录不透出价格，robots 禁 `/flights/ShowFareFirst*`） | 机票价格实时波动 + 需登录/风控 | 只存**区间**（如“¥600–1300”），note 写“参考区间，未取实时价” |

**建议口径（一句话给老板）**：城市/景点/火车票自动建库，酒店只做“参考价区间”并配后台批量导入，机票只给区间。全站统一标注“参考价，价格以各平台实时为准”。

### 2.2 酒店：四平台未登录实测（本次调研最关键的一块）

**总结论：四家全部拿不到“未登录可读的价格”。**

| 平台 | 实测 URL | 现象（实测） | 能否读价 |
| --- | --- | --- | --- |
| 携程 PC 列表 | `https://hotels.ctrip.com/hotels/list?city=6`（city=6=大连） | 无验证码、正常渲染 3675 家酒店，**酒店名/评分/房型/距离全有**，但每张卡片价格位置显示 **“登录以查看会员价”**；页面内 `document.body.innerText` 里 ¥ 数字个数 = 0（只有筛选项 ¥150-250 这类价格带） | ❌ |
| 携程 PC 静态 SEO 列表 | `https://hotels.ctrip.com/hotel/dalian6` | 服务端渲染 14 家酒店名 + 评分 + 位置，价格位置是占位文字 **“酒店价格”**（异步加载，未登录不填） | ❌ |
| 携程 WAP 详情 | `https://wap.ctrip.com/html5/hotel/hoteldetail/430039.html`（大连中山大酒店） | 页面完整加载（6612 字：装修年份/评分/164 条点评/地址/距地铁 230 米），价格区先是“正在为您查询房间价格, 请耐心等待 → 加载中...”，等 7 秒后**依然 0 个 ¥**，底部变成 **“登录享最高85折·4项免费权益 / 立即登录”** | ❌ 异步加载 + 登录墙 |
| 携程手机版列表 | `https://m.ctrip.com/webapp/hotel/chengdu28` | 简体酒店名/评分/收藏数都有，价格位置写 **“登录看低价”** | ❌ |
| 去哪儿 | `https://hotel.qunar.com/city/dalian`、`https://touch.qunar.com/hotel/` | 两次都 **302 回 www.qunar.com 首页**，落地页只有 288 字的 SPA 壳，无任何酒店数据（风控识别为自动化） | ❌ |
| 美团 | `https://hotel.meituan.com/dalian/` | **HTTP 403 Forbidden / openresty**（23 字节纯错误页，无验证码、无重定向，直接拒） | ❌ |
| 同程 | `https://hotel.ly.com/` | 同样 **403 Forbidden / openresty** | ❌ |
| 飞猪 | `https://hotel.fliggy.com/hotelList.htm?cityCode=DLI` | 跳转 **error.taobao.com**（“亲，请登录 / 抱歉！页面无法访问”），阿里登录+风控墙 | ❌ |
| **携程集团国际站（唯一能读到真价）** | `https://tw.trip.com/hotels/list?city=6&curr=CNY` | **未登录直接看到逐家酒店 CNY 价（原价+折扣价，含税）**，如“宜客宜家酒店 CNY181 → CNY114 / 含税项及费用”；每家还有英文名、9.7/10 评分、点评数、房型、位置 | ✅ 技术上能，**但 robots.txt 明确 `Disallow: /hotels/list`，不能用于生产**（见 §2.6） |

价格是**异步加载**还是**静态 HTML**：携程酒店列表/详情页价格是**异步接口 + 登录校验**（占位文字先出现，无登录则永不填数）；Trip.com 国际站价格也是异步，但不需要登录，等约 8–10 秒即渲染出来。

配套事实：Trip.com 只提供繁体/英文，城市 id 与携程一致（大连=6、北京=1、成都=28），需要做一次“繁体名→简体名”映射。

**12306 官方：抓不了。**
- `https://kyfw.12306.cn/otn/leftTicket/query?...` 直接请求 → 返回 **2042 字节错误页**（“网络可能存在问题，请您重试一下！”），不是 JSON。
- `https://www.12306.cn/robots.txt` 也返回同一个错误页（无 robots 声明，但整站对非浏览器请求一律拦）。
- 结论：12306 只服务它自己的前端会话（cookie + 设备指纹 + 滑块）。**不要碰 12306。**

**飞机票：只能给区间。**
- `https://flights.ctrip.com/online/list/oneway-dlc-bjs?depdate=2026-10-20...`（大连→北京）：页面只剩 717 字的导航壳 + 页脚，等 21 秒后依然 **0 个价格、无任何航班行**（“航班号/起飞/经济舱”一个都没有）。
- `https://flights.ctrip.com/schedule/dalian-beijing.html`：被重定向到通用“航班时刻表”首页，只有城市字母索引，**不含票价**。
- robots.txt 亦禁 `/flights/ShowFareFirst*`、`/flights/graphql/`。
- → 结论：机票**没有稳定公开价**，只能存“区间/参考价”。

| 站点 | robots.txt 关键内容（实测原文） | 判定 |
| --- | --- | --- |
| `www.mafengwo.cn` | `User-agent: *` → **`Disallow: /`** | 🚫 全站禁止抓取；实际还有腾讯滑块验证码 |
| `hotels.ctrip.com` | `User-agent: *` → **`Disallow: /`**，仅 `Allow: /hotels/*.html`、`/flagship/*/*.html` 白名单 | 🚫 酒店列表/详情页一律禁；且价格本身要登录 |
| `www.ctrip.com` | 只有 `/bin/`、`/Member/` 等少数 Disallow，末尾 `Allow: /` | 相对宽松 |
| `you.ctrip.com`（景点攻略） | `Disallow: /search/*`、`/ajax`、`/ajaxnew`、**`/*?*`**（禁带参数 URL）、`/sitemap-*` 等；其余允许 | ✅ 用的正是无参数静态页 `/sightlist/dalian4.html`，符合 robots |
| `trains.ctrip.com` | `User-Agent: *` → 只禁 `/TrainBooking/Search*` 和各席别列表路径 | ✅ `/trainbooking/<城市>-<城市>` 不在禁止清单内 |
| `tw.trip.com` | `User-agent: *` → 含 **`Disallow: /hotels/list`**、`/hotels/detail/?hotelId=*`、`/flights/showfarefirst*` | 🚫 虽然技术上能读到 CNY 价格，**但 robots 明确禁止该路径，不能作为生产数据源** |
| `www.qunar.com` | 无 `User-agent: *` 段，只有针对具体 bot 的规则和路径黑名单（`/twell/hotel/` 等） | ⚠️ 灰区；实际已被风控（跳首页） |
| `www.meituan.com` / `hotel.ly.com` | robots 请求被“连接被意外关闭”；页面直接 403 | 🚫 强反爬 |
| `www.fliggy.com` | robots 请求返回淘宝异常页 | 🚫 阿里风控墙 |
| `lbs.amap.com` | `Allow: /` + sitemap | ✅ 走正规 API 即可 |
| `www.mct.gov.cn`（文旅部） | robots.txt 404（无声明） | ✅ 可读 |
| `www.12306.cn` | 请求被拦，返回错误页 | 🚫 不要碰 |

**合规建议（结论）：**
1. **只抓“明确允许 + 静态页 + 无需登录”的三类**：you.ctrip.com 的景点列表页、trains.ctrip.com 的线路页、民政部区划页。频控做到每人/每 IP 每秒 < 1 次、遵守 `Cache-Control`、不绕验证码、不伪造登录态。
2. **酒店价格改走“参考价人工整理 + 后台批量导入”**——这不是妥协，是唯一能长期活着的做法：所有平台把价格当核心资产放在登录墙后，任何“抓到实时价”的方案都会在 1–4 周内被封或需要持续维护登录态（法律与稳定性双输）。
3. **明确不做**：马蜂窝（robots 全禁）、12306、美团/同程（403）、飞猪（登录墙）、tw.trip.com 的 `/hotels/list`（robots 禁）。
4. 页面上必须写清“**参考价，价格以携程/美团等平台实时显示为准**”，并在数据行上存 `source_url` + `captured_at`，方便追溯和申诉。

## 4. 落地方案（推荐做法与工作量）

### 4.1 推荐三层结构

| 层 | 数据 | 获取方式 | 更新频率 |
| --- | --- | --- | --- |
| A 类·可自动 | 城市（78）、景点票（40 城 × 8 = 320）、火车票（约 80 条线路） | 三个静态页抓取脚本（民政部 / you.ctrip.com / trains.ctrip.com），单次跑完即入库 | 月更 |
| B 类·参考价 | 酒店（40 城 × 8 = 320 家） | **管理员后台 CSV 批量导入**（最省），模板 8 列：城市/酒店名/档位/价格下限/上限/地址/来源/采集日期 | 季更或按需 |
| C 类·区间 | 机票 | 人工维护区间表（按航线大类：短途 300–800 / 中程 500–1300 / 长途 800–2000），或干脆先不做 | 半年更 |

### 4.2 为什么 B 类必须走 CSV（实测数字说话）

- 未登录在携程/美团/飞猪/去哪儿**一家都看不到酒店价**（§2.2），要看价必须登录 → 自动化 = 伪造登录态 = 必被封。
- 唯一能读到价的 Trip.com 路径 `/hotels/list` **被 robots 明确 Disallow**，不能当生产源。
- 因此“每家酒店打开详情页看一眼价格”是唯一可行的原路径，代价见下表。

### 4.3 工作量估算（按实测耗时折算）

| 任务 | 规模 | 单次操作耗时（实测） | 纯自动化耗时 | 人工耗时 |
| --- | --- | --- | --- | --- |
| 城市清单 | 1 页（民政部 1.45MB） | 抓 3 秒 + 解析 1 秒 | ≈ 1 分钟 | 0 |
| 景区门票 | 40 城 × 1 页（每页 10 条，够 8 条） | 打开+渲染 ≈ 6–8 秒/页 | **≈ 6 分钟**（40 页） | 抽检 40 条 ≈ 40 分钟 |
| 5A 缺价补齐（故宫/天坛/颐和园类） | 约 30 个 | 官网/百科 1–2 分钟/个 | - | ≈ 1 小时 |
| 火车票 | 约 80 条线路（40 城 × 2） | ≈ 5–6 秒/页 | **≈ 8 分钟** | 0 |
| 酒店名称（若用高德） | 40 城 × 8 | 1 次 API/城（1 秒） | ≈ 3 分钟（含申请 key 的 0.5 天等待） | 0 |
| **酒店参考价（逐页人工）** | **320 家** | **每家要登录平台→搜城市→翻页→点开→记录，实测 1.5–3 分钟/家** | 不可自动化 | **8–16 小时**（≈320 次详情页操作，40 个城市各 8 次） |
| **酒店参考价（CSV 批量导入）** | 320 行 | 一次导入 | - | **1.5–3 小时**（找现成价目/榜单 + 校对） |

**结论：A 类全自动 < 20 分钟就能建库；B 类用 CSV 是 2 小时，用逐页人工是 8–16 小时（差 5 倍以上）。**

### 4.4 具体实施顺序（建议）

1. **先做 A 类**（1 天内可上线）：写 3 个一次性脚本 → 生成 `seed-cities.sql` / `seed-attractions.sql` / `seed-transports.sql`，直接 `npm run db:setup` 灌库。这一步就能让“40 个城市能查、能选景点、能算车费”。
2. **再做 B 类的骨架**：给 hotels 表加 `price_low` / `price_high` / `source_url` / `captured_at` 四个字段（或先用 note 拼字符串），后台加一个“CSV 导入”按钮。先只填 3 个城市做样板。
3. **酒店参考价来源建议**（合规且省事）：高德 POI 拿名单 → 用平台筛选条件反推价格带（携程列表页的 ¥150-250/¥250-300 分档是全国统一分档，可作粗口径）→ 人工填区间。**不要**试图抓实时房价。
4. **页面文案**：所有价格旁加“参考价”，酒店卡片加“实际价格以携程/美团实时为准”。

### 4.5 风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| you.ctrip.com 改版/加风控 | 景点抓取失效 | 抓取脚本按“页面结构 + 兜底正则”双路解析；改版告警；保留人工补录入口 |
| 携程价格“起价”不等于门市价 | 用户觉得不准 | 同时展示 market_price（原价），note 写“平台起价” |
| 火车票价随线路调整 | 数据过期 | 存 captured_at，月更；页面标“票价以 12306 为准” |
| 酒店参考价偏差 | 算总花费偏差 30%+ | 存区间而非单值，前端按区间中位算，并提示“浮动区间” |
| 合规投诉 | 站点被要求下线 | 只抓 robots 允许的 3 个来源；不存图片；不绕验证码；保留 source_url 可随时清理 |

## 5. 还差什么（如实说明）

1. **“官方热门旅游城市名单”不存在**：只能拿“平台热度”和“行政区划”两个代理指标。如果老板要“权威”，建议引用文旅部《“十四五”旅游业发展规划》里的重点旅游城市提法（新闻口径），但它是文字表述，不是可机读名单。
2. **酒店价格没有合规自动化路径**——这是本次调研最硬的结论，换谁来做都一样。要更准只能接商业数据服务（如携程/美团的企业级 API，需商务合作+付费），本调研未涉及报价。
3. **机票区间是估算**：如果要准确，需要接航司/GDS 或第三方机票 API（付费）。
4. 本次未测试：`qunar` 的移动端备用域名、`ctrip` 的海外英文站（`www.trip.com/hotels/list`，robots 同样禁 `/hotels/list`）。
