> 项目位置：`D:\旅游费用查询网站`　技术栈：Vue3 + Express + MySQL　代码用 VSCode 打开这个目录就能改，数据库用 Navicat 连本地 MySQL（root / 空密码 / travel_cost 库）。

| 模块 | 内容 |
| --- | --- |
| 用户端 | 注册、登录、选目的地、查酒店/景点门票/城际车费、勾选后一键算这趟总价 |

## 二、三步跑起来

```powershell
cd D:\旅游费用查询网站
npm run build          # 装依赖 + 打包前端（代码改过才需要重跑）
$env:PORT=3000; npm start   # 起服务，浏览器打开 http://localhost:3000
```

开发模式（改代码即时生效）：`npm run dev:server` + `npm run dev:web`，访问 http://localhost:5173

重置数据：`npm run db:setup`（会重建表并刷回样例数据，管理端改过的价格会被覆盖）

## 三、三个身份

1. 新用户：打开网址 → 注册（只要用户名+密码）→ 首页选城市（348 个，可搜索）→ 勾酒店/门票，再选出发地查车费 → 算总价看明细；每张卡片可点「去携程看实时价」核对当天价格。
2. 管理员：`admin` / `123456` → 自动进「数据管理」；改完价格，用户端刷新立刻是新价（没有缓存）。
3. 普通用户访问管理端网址会被踢回首页并提示「只有管理员能进管理端」。

## 七、已知限制（先说清楚，别当 bug）

1. 没人访问 15 分钟，Render 免费实例会休眠，第一条请求要等约 50 秒。
2. 车费口径是「A 地到 B 地的一种交通方式单价」，不做实时票价、不做班次时刻。
3. 门票按「一人一次」计，没做多人同行人数选择；不含吃饭购物。
4. 管理端没做分页（18 条量级用不上），也不支持上传图片。
5. 云端的 TLS/证书链路没在真机上验证过（没有你的云账号）；真报证书错时把 `DB_SSL_REJECT_UNAUTHORIZED` 设 false。
6. A 那条免费隧道网址每次重启都会变（随机子域名），且要电脑开着；想固定网址只有 C 那条路。
7. 车费是全国两两互连的**测算价**（按城市直线距离估算），不是实时票价；真实票价以 12306/携程为准，页面已标注。
7.1 Netlify 的接口是 Serverless 函数，**冷启动约 1-2 秒**（闲置一段时间后第一次打开会慢一下），之后很快。
7.2 云库是 TiDB Serverless 免费档（5GiB 存储 / 5000 万请求单元）；当前用量远低于额度。
8. 酒店/景点价格是**参考价**（各平台价位整理），不是实时房价；点「去携程看实时价」看当天真实价。
9. 本地 MySQL 目前是手动启动的实例（datadir=`D:\mysql-data`，端口 3306）；电脑重启后如果连不上，用 `D:\mysql\bin\mysqld.exe --no-defaults --basedir=D:\mysql --datadir=D:\mysql-data --port=3306` 起一下。
