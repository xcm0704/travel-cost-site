# 旅游费用查询网站 · 需求与技术方案 V1.0

> 项目根目录：`D:\旅游费用查询网站`
> 本文是**前后端唯一契约**。前端与后端两路并行开发，都按这份文件写，不许自行改约定；确需改动先找 Lead 确认。

---

## 一、要做什么（大白话）

一个查旅游花多少钱的网站，手机打开也能用。

- **普通用户**：注册账号 → 登录 → 选一个目的地（比如大连）→ 查当地的酒店价格、景点门票、从自己城市到目的地的车费 → 勾几项一键算出「这趟大概多少钱」。
- **管理员**：用户名 `admin` 密码 `123456`，不用注册，直接登录。比用户端多三个页面：数据管理（增/删/改 目的地、酒店、门票、车费）、数据总览（各表条数）、注册用户列表。
- **不做**：下单、支付、订单、短信验证、找回密码。

## 二、已敲定的决策

## 四、数据库设计

字符集统一 `utf8mb4` / `utf8mb4_unicode_ci`，金额用 `DECIMAL(10,2)`，时间 `DATETIME`。

```sql
users(id INT PK AI, username VARCHAR(50) UNIQUE NOT NULL, password_hash VARCHAR(100) NOT NULL,
      role ENUM('user','admin') NOT NULL DEFAULT 'user', created_at DATETIME DEFAULT CURRENT_TIMESTAMP)

destinations(id INT PK AI, name VARCHAR(50) UNIQUE NOT NULL, province VARCHAR(50) DEFAULT '',
             intro VARCHAR(255) DEFAULT '', updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)

hotels(id INT PK AI, destination_id INT NOT NULL, name VARCHAR(100) NOT NULL, level VARCHAR(20) DEFAULT '',
       address VARCHAR(200) DEFAULT '', price_per_night DECIMAL(10,2) NOT NULL,
       note VARCHAR(255) DEFAULT '', updated_at DATETIME ..., FOREIGN KEY(destination_id) REFERENCES destinations(id))

attractions(id INT PK AI, destination_id INT NOT NULL, name VARCHAR(100) NOT NULL,
            ticket_price DECIMAL(10,2) NOT NULL, open_time VARCHAR(100) DEFAULT '',
            note VARCHAR(255) DEFAULT '', updated_at DATETIME ..., FOREIGN KEY(destination_id) REFERENCES destinations(id))

transports(id INT PK AI, from_city VARCHAR(50) NOT NULL, to_city VARCHAR(50) NOT NULL,
           mode VARCHAR(20) NOT NULL,            -- 高铁 / 动车 / 飞机 / 大巴 / 自驾
           duration_minutes INT NOT NULL DEFAULT 0, price DECIMAL(10,2) NOT NULL,
           note VARCHAR(255) DEFAULT '', updated_at DATETIME ...)
```

初始数据（`db:setup` 自动灌入，可重复执行不炸）：
- `admin` / `123456`（role=admin，bcrypt 哈希入库）
- 5 个目的地：大连、北京、上海、杭州、成都（各带省份 + 一句介绍）
- 每个目的地 3 家酒店（价格 180~1200 区间，酒店名要像真的）、3 个景点（真实景点名 + 门票价）
- 12+ 条城际交通（沈阳→大连、北京→大连、北京→上海、上海→杭州、北京→成都、成都→杭州 等，含返程方向，mode 覆盖高铁/飞机/大巴）
- 灌数据用 `INSERT ... ON DUPLICATE KEY UPDATE` 或先查后插，保证重复跑不报错

## 五、接口契约（前后端唯一约定）

后端统一前缀 `/api`。请求/响应都是 JSON（`Content-Type: application/json`）。
成功直接返回数据对象或数组；失败返回对应 HTTP 状态码 + `{ "error": "中文提示" }`。
日期时间统一以字符串 `YYYY-MM-DD HH:mm` 返回。

### 5.1 鉴权（无需 token）

| 方法 | 路径 | 请求体 | 成功响应 | 失败 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/register` | `{username, password}` | 201 `{token, user:{id,username,role}}` | 400 `{error}` |
| POST | `/api/auth/login` | `{username, password}` | 200 `{token, user:{id,username,role}}` | 401 `{error:"用户名或密码不对"}` |
| GET | `/api/auth/me` | Bearer token | 200 `{id,username,role}` | 401 |

注册校验（都要中文提示）：用户名 3~20 字且只许中英文数字下划线；密码 6~32 字；用户名重复 → `这个用户名已经有人用了`；用户名是 admin（不分大小写）→ `这个名字不能用`。
注册成功一律 role=user，**不允许**前端指定角色。注册即登录（直接给 token）。

### 5.2 用户端查询（都要登录，Bearer token；未登录 401）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/destinations` | `[{id,name,province,intro}]` 全部目的地 |
| GET | `/api/cities` | `{cities:[string]}` 目的地名 ∪ 交通表里的 from_city/to_city，去重排序（车费下拉用） |
| GET | `/api/hotels?destinationId=&q=` | `[{id,destinationId,destinationName,name,level,address,pricePerNight,note}]`，q 模糊匹配名称，按价格升序 |
| GET | `/api/attractions?destinationId=&q=` | `[{id,destinationId,destinationName,name,ticketPrice,openTime,note}]` |
| GET | `/api/transports?from=&to=&mode=` | `[{id,fromCity,toCity,mode,durationMinutes,price,note}]`，全部参数可选，按价格升序 |

### 5.3 一键算总价

`POST /api/estimate`

```json
{
  "destinationId": 1,
  "nights": 2,
  "hotelId": 3,
  "attractionIds": [1, 2],
  "fromCity": "沈阳",
  "toCity": "大连",
  "transportId": null,
  "roundTrip": true
}
```

计算规则：
1. 门票 = 所选景点门票价之和（`attractionIds` 必须都属于该目的地，否则 400）。
2. 住宿 = 所选酒店 `pricePerNight × nights`（nights 1~30，默认 1；不选酒店则为 0 且 `hotel:null`）。
3. 车费：`transportId` 为空时，在 `from_city=fromCity 且 to_city=toCity` 里取价格最低的一条；没有记录则 400 `{error:"这个路线还没有录入车费"}`。
4. 返程：`roundTrip=true` 时找反向记录（`from_city=toCity 且 to_city=fromCity 且 mode 相同`），有就用它的价，没有就按去程同价算；`roundTrip=false` 只算去程。

响应：

```json
{
  "destination": { "id": 1, "name": "大连" },
  "nights": 2,
  "hotel": { "id": 3, "name": "大连星海假日酒店", "pricePerNight": 480 },
  "attractions": [{ "id": 1, "name": "老虎滩海洋公园", "ticketPrice": 220 }],
  "transport": {
    "mode": "高铁",
    "go": { "from": "沈阳", "to": "大连", "mode": "高铁", "price": 145 },
    "back": { "from": "大连", "to": "沈阳", "mode": "高铁", "price": 145 }
  },
  "items": [
    { "label": "老虎滩海洋公园 门票", "amount": 220 },
    { "label": "大连星海假日酒店 × 2 晚", "amount": 960 },
    { "label": "沈阳 → 大连 高铁", "amount": 145 },
    { "label": "大连 → 沈阳 高铁（返程）", "amount": 145 }
  ],
  "total": 1470
}
```

### 5.4 管理端（必须 role=admin，否则 403 `{error:"只有管理员能做这个"}`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/overview` | `{users,destinations,hotels,attractions,transports}` 各表条数 |
| GET | `/api/admin/users` | `[{id,username,role,createdAt}]`，按注册时间倒序 |
| GET | `/api/admin/destinations` | 全量，含 `updatedAt` |
| GET | `/api/admin/hotels?destinationId=&q=` | 全量（不限目的地），含 `destinationName,updatedAt` |
| GET | `/api/admin/attractions?destinationId=&q=` | 同上 |
| GET | `/api/admin/transports?from=&to=` | 全量 |
| POST | `/api/admin/{资源}` | 新增，201 + 新建对象 |
| PUT | `/api/admin/{资源}/:id` | 修改，200 + 修改后对象 |
| DELETE | `/api/admin/{资源}/:id` | 删除，200 `{ok:true}` |

四个资源的资源名：`destinations` / `hotels` / `attractions` / `transports`。

写接口字段（少字段或类型不对 → 400 中文提示）：
- destinations：`{name, province, intro}`
- hotels：`{destinationId, name, level, address, pricePerNight, note}`
- attractions：`{destinationId, name, ticketPrice, openTime, note}`
- transports：`{fromCity, toCity, mode, durationMinutes, price, note}`

约束：删除还有酒店/景点挂着的目的地 → 400 `这个目的地下面还有酒店或门票，先删掉它们`；改数据后用户端查询立即看到新值（不缓存）。

## 六、前端页面清单

| 路由 | 页面 | 要点 |
| --- | --- | --- |
| `/login` | 登录 | 用户名/密码；admin 登录后自动跳 `/admin/data` |
| `/register` | 注册 | 用户名/密码/确认密码，前端同样做长度校验 |
| `/` | 首页查询 | 顶部目的地选择（卡片或下拉）→ 三个标签页：酒店 / 门票 / 车费（车费页有出发地→目的地 + 方式筛选）；每项可勾选加入「行程清单」；页脚固定条显示当前合计 + 「算总价」按钮 |
| `/estimate` | 总价明细 | 展示 `items` 明细 + `total`，可返回改选 |
| `/admin/data` | 数据管理 | 四个标签页（目的地/酒店/门票/车费），表格 + 新增 + 编辑弹窗 + 删除二次确认，改完列表自动刷新 |
| `/admin/overview` | 数据总览 | 顶部 5 个数字卡片（用户/目的地/酒店/门票/车费） |
| `/admin/users` | 注册用户 | 表格：ID、用户名、角色、注册时间 |

路由守卫：未登录访问任何内页 → 跳 `/login`；非 admin 访问 `/admin/*` → 跳 `/` 并提示。
导航：普通用户只看到「查费用 / 退出」；admin 看到「数据管理 / 数据总览 / 注册用户 / 退出」。
样式：主色一个（建议青蓝色系），卡片圆角 + 轻阴影，表格在窄屏可横向滚动，按钮 44px 高（手机好点）。

## 七、本地跑起来

```powershell
# 1. 初始化数据库（建库建表 + 灌样例数据）
cd D:\旅游费用查询网站\server

# 2. 起后端（http://localhost:3000）

# 3. 起前端（http://localhost:5173，/api 代理到 3000）

# 4. 生产模式自测：web 打包后由 Express 直接托管

```

## 八、上线（第二阶段）

1. 代码推到 GitHub。
2. TiDB Cloud 建 Serverless 集群 → 拿到 host/user/password → 用 Navicat 连上执行 `schema.sql` + `seed.sql`。
3. Render 建 Web Service（Node 环境），环境变量：`DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME/DB_SSL=true/JWT_SECRET`，Build 命令装前后端依赖并打包前端，Start 命令起 Express。
4. 得到 `https://xxx.onrender.com` 网址，直接发给好友。
   注意：免费实例 15 分钟没人访问会休眠，第一条请求要等约 50 秒。

## 九、验收标准（谁都得过这几条）

1. `npm run db:setup` 一条命令建库建表灌数据，重复执行不报错。
2. 后端 `http://localhost:3000/api/health` 返回 `{ok:true}`。
3. 新用户名注册 → 拿到 token → 能查目的地/酒店/门票/车费 → 算总价数字对得上（手工核算一遍）。
4. `admin`/`123456` 登录成功；错密码登录失败提示中文；普通用户访问 `/api/admin/users` 返回 403。
5. 管理员改一条酒店价格 → 用户端刷新立刻看到新价；新增/删除同链路都通。
6. `npm run build` 无报错，Express 托管 `web/dist` 时刷新任意前端路由不 404。
7. 手机宽度 375px 下首页、数据管理页不横向溢出、按钮可点。
8. 每一步都要有真实命令输出或浏览器截图作为证据。
