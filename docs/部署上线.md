# 部署上线 · 从今天发链接到云上有个正式网址

> 这份文件的用处：把「代码在这台电脑上」变成「朋友点开网址就能用」。
> 全文分两条路：**A 今天就能发（局域网，5 分钟）**、**B 正式的云上公网地址（约 1 小时，要注册账号）**。
> 标注 ⭐ 的步骤必须**你本人**动手：注册账号、点授权按钮、把密码贴进控制台，我（AI）不碰你的云账号。

---

## A. 今天就能发给好友（局域网，实测通过）

前提：你和朋友的手机/电脑连着**同一个 Wi-Fi**（同一路由器），电脑不关机、不睡眠。

```powershell
cd D:\旅游费用查询网站
npm run build                       # 装依赖 + 打包前端（只需在代码变过之后跑）
$env:PORT=8080; npm start           # 一个进程同时提供页面和 /api
```

看到这几行就是成了：

```
后端已启动： http://localhost:8080（监听 0.0.0.0，同一局域网可用本机 IP 访问）
数据库： root@127.0.0.1:3306/travel_cost | TLS：关闭
静态托管： D:\旅游费用查询网站\web\dist
```

查本机局域网 IP：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } | Select-Object IPAddress, InterfaceAlias
```

本机当前实测结果是 `192.168.1.11`（以太网，DHCP 分配，重启路由器可能会变）。于是发给好友的网址就是：

```
http://192.168.1.11:8080
```

实测记录（同一台机器上 curl 自己的局域网 IP，等价于朋友从局域网访问）：

| 请求 | 结果 |
| --- | --- |
| `GET http://192.168.1.11:8080/api/health` | 200 `{"ok":true}` |
| `GET http://192.168.1.11:8080/` | 200 `text/html`，542 字节，含 `<div id="app">` |
| `GET http://192.168.1.11:8080/login` | 200 `text/html`（SPA 刷新不 404） |
| `POST http://192.168.1.11:8080/api/auth/login` | 200，admin 登录拿到 183 字符 token |
| `GET http://192.168.1.11:8080/api/destinations`（带 token） | 200，5 条 |
| `node server/scripts/smoke.js`（`BASE=http://192.168.1.11:8080`） | **52 项断言全过** |

### 朋友打不开怎么办

1. **先确认在同一 Wi-Fi**：手机连的是不是和你电脑同一个路由器名字。
2. **Windows 防火墙挡了**：第一次运行 `npm start` 时如果弹出「是否允许 Node.js 访问网络」，要勾**专用网络**允许。没弹出或误点了「取消」，用管理员 PowerShell 手动放行 ⭐（要你点「是」授权）：

   ```powershell
   New-NetFirewallRule -DisplayName "travel-cost 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
   ```

3. **手机能打开页面但登录报错**：确认你发的是 `http://192.168.x.x:8080`（页面和接口是同一个端口，不要另配 3000）。
4. **IP 变了**：重新跑上面那条查 IP 的命令，或去路由器里把这台机器设成固定 IP。
5. **电脑睡眠了**：Windows 设置 → 电源 → 关闭「睡眠」。关了电脑/服务，网址立刻失效。

> 这一步就是「今天能发给好友」的最短路径。缺点是只能局域网内看，且电脑必须开着。想要真正的公网网址，继续往下看 B。

## B. 正式公网地址：Render（跑程序）+ TiDB Cloud（存数据）

两项都是免费额度，够这个小站用。**注册、授权、点按钮这些必须你本人做（⭐）。**

### 第 1 步 ⭐ 把代码推到 GitHub

1. ⭐ 有 GitHub 账号就跳过；没有去 https://github.com/signup 注册（邮箱 + 密码 + 验证）。
2. ⭐ 网页上 New repository → 名字填 `travel-cost` → **Private**（想公开也行）→ 不要勾任何初始化文件 → Create。
3. 本地推上去（仓库已经初始化好并有第一次提交了）：

   ```powershell
   cd D:\旅游费用查询网站
   git remote add origin https://github.com/<你的用户名>/travel-cost.git
   git branch -M main
   git push -u origin main
   ```

   第一次推会弹窗让你**在浏览器里登录 GitHub 并授权**（⭐ 你点）。密码是 Personal Access Token，不是登录密码——弹窗若要求 token，去 GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token，勾 `repo` 权限，复制生成的串当密码。
4. 推完在 GitHub 网页上能看到 47 个文件，**看不到** `node_modules`、`web/dist`、`server/.env`（.gitignore 已挡住，这是故意的）。

### 第 2 步 ⭐ TiDB Cloud 建 Serverless 集群、拿连接信息

1. ⭐ 打开 https://tidbcloud.com → Sign up（用 GitHub / Google / 邮箱登录都行）。
2. ⭐ 控制台左侧 **Clusters** → **Create Cluster** → 选 **Serverless**（不是 Dedicated，Dedicated 收费）。
3. ⭐ 填写：
   - Cluster Name：`travel-cost`
   - Cloud Provider / Region：`AWS` + `Singapore (ap-southeast-1)`（离中国近，延迟低）
   - 其他保持默认 → **Create**
4. ⭐ 等 1~3 分钟，状态变成 **Active**。
5. ⭐ 点进集群 → 右上 **Connect** → 弹窗里：
   - Connect With 选 **General**（或 MySQL CLI，能看到完整连接串）
   - 记下四个值，等下要贴到 Render：
     - **Host**：形如 `gateway01.ap-southeast-1.prod.aws.tidbcloud.com`
     - **Port**：`4000`
     - **User**：形如 `3xK9aBcDeF.root`
     - **Password**：点 **Generate Password** 生成，**立刻复制保存**（关掉弹窗就看不到了，看不到只能重新生成）
   - 弹窗里还有个 **CA cert** 下载链接；用 Navicat/本项目的 `DB_SSL=true` 时走系统信任链即可，不用手动下证书。
6. ⭐ 记住 TiDB 强制 TLS：连接一律要开 SSL（也就是 `DB_SSL=true`）。
7. 免费额度提示：Serverless 每月有免费的行读写额度（约 5 GB 存储 + 5000 万行读/写），这个小站远用不到。⚠️ 建集群时若被要求绑信用卡，说明你选的不是免费档，退回去重新选 **Serverless**（它的免费额度不需要绑卡，但可能要求验证邮箱）。

### 第 3 步 建表 + 灌样例数据（两条路，选一条）

#### 路线一（推荐，一条命令，不用装 Navicat）

在**你自己的电脑**上，把环境变量指到云库，再跑项目自带的初始化脚本。它会 `CREATE DATABASE IF NOT EXISTS travel_cost`、建 5 张表、灌 5 个目的地/15 家酒店/15 个景点/18 条车费、写入 admin 账号。

```powershell
cd D:\旅游费用查询网站
$env:DB_HOST='gateway01.ap-southeast-1.prod.aws.tidbcloud.com'   # 换成你的 Host
$env:DB_PORT='4000'
$env:DB_USER='3xK9aBcDeF.root'                                    # 换成你的 User
$env:DB_PASSWORD='你刚才生成的密码'
$env:DB_NAME='travel_cost'
$env:DB_SSL='true'
npm run db:setup
```

成功的输出长这样：

```
目标数据库： 3xK9aBcDeF.root@gateway01.ap-southeast-1.prod.aws.tidbcloud.com:4000/travel_cost | TLS：开启（TLSv1.2，校验证书）
数据库已就绪：travel_cost
建表完成（IF NOT EXISTS，重复跑不会报错）
样例数据已灌入（ON DUPLICATE KEY UPDATE，重复跑不会重复插入）
各表条数：
  users         1
  destinations  5
  hotels        15
  attractions   15
  transports    18
管理员账号：admin / 123456
```

> 这个环境变量只在当前 PowerShell 窗口有效，关掉就没了，不影响你本地的 `server/.env`。

#### 路线二 用 Navicat 手动执行（契约里写的路子）

1. ⭐ Navicat → 连接 → MySQL：
   - 连接名：`tidb-travel-cost`
   - 主机：你的 Host（**不要**带 `mysql://` 之类前缀）
   - 端口：`4000`
   - 用户名 / 密码：上面记的
   - **SSL 选项卡**：勾上「使用 SSL / TLS」，模式选「需要」，验证证书勾上（TiDB 用公有 CA，能验过）
2. 连上后 **新建查询**，把 `server/db/schema.sql` 整个文件内容粘进去 → 运行。它会先 `CREATE DATABASE IF NOT EXISTS travel_cost` 再 `USE travel_cost` 建表。
   （TiDB 的 root 账号可以建库；如果报没有权限，在 TiDB 网页的 **SQL Editor** 里先执行一次 `CREATE DATABASE travel_cost;`）
3. 再新建查询，粘 `server/db/seed.sql` → 运行。它含 admin 账号和全部样例数据，重复执行不会重复插入。
4. 刷新左侧库表，应该看到 5 张表；点开 `destinations` 有 5 行。

### 第 4 步 ⭐ Render 建 Web Service、填环境变量

**方式甲：用仓库里的 render.yaml（Blueprint，少填很多）**

1. ⭐ https://render.com → Get Started → **用 GitHub 账号登录并授权**（你点 Allow）。
2. ⭐ 控制台 → **New +** → **Blueprint** → 选 `travel-cost` 仓库 → Apply。
3. ⭐ 它会自动读 `render.yaml`，弹出几个 `sync: false` 的变量让你填：`DB_HOST`、`DB_USER`、`DB_PASSWORD`（`JWT_SECRET` 会自动随机生成）。
4. ⭐ 点 **Apply / Create**，等构建。

**方式乙：手动 New + → Web Service（不想用 yaml 就按这个填）**

1. ⭐ New + → **Web Service** → 选 `travel-cost` 仓库（首次要授权 Render 访问该仓库）。
2. ⭐ 填：
   - **Name**：`travel-cost`（决定网址：`https://travel-cost.onrender.com`，重名就换一个）
   - **Region**：Singapore
   - **Branch**：`main`
   - **Runtime / Language**：Node
   - **Build Command**：`npm run build`
   - **Start Command**：`npm start`
   - **Instance Type / Plan**：**Free**
3. ⭐ **Advanced → Health Check Path**：`/api/health`
4. ⭐ **Environment Variables**（一个都别漏）：

   | Key | Value | 说明 |
   | --- | --- | --- |
   | `NODE_ENV` | `production` | 生产模式 |
   | `DB_HOST` | 你的 TiDB Host | 必填 |
   | `DB_PORT` | `4000` | TiDB 默认 4000 |
   | `DB_USER` | 你的 TiDB 用户名 | 形如 `xxx.root` |
   | `DB_PASSWORD` | 你生成的密码 | 必填 |
   | `DB_NAME` | `travel_cost` | 与初始化时一致 |
   | `DB_SSL` | `true` | TiDB 强制 TLS |
   | `DB_SSL_REJECT_UNAUTHORIZED` | `true` | 报证书错就改 `false` |
   | `JWT_SECRET` | 32 位以上随机串 | 或者用 Render 的 Generate 按钮 |
   | `JWT_EXPIRES_IN` | `7d` | 登录 7 天有效 |

   > 不要设 `PORT`：Render 会自己注入 `PORT`，程序已经按环境变量读。
5. ⭐ **Create Web Service**，看 **Logs** 里滚：`added N packages` → `vite build` → `后端已启动`。

### 第 5 步 验收（打开网址试一遍）

1. 浏览器打开 `https://<你的服务名>.onrender.com/api/health` → 应显示 `{"ok":true}`。
   这一步过了，说明**程序起来了 + 数据库连上了**（health 不查库，但要紧的下一步会查）。
2. 打开 `https://<你的服务名>.onrender.com/` → 首页；点「注册」注册一个账号 → 应该能查到目的地/酒店。
   这一步过了，说明**数据库读得通**。
3. 用 `admin` / `123456` 登录 → 能进「数据管理」，说明**写权限也通**。
4. 刷新一下 `/estimate` 这种子页面，不能 404（Express 有 SPA fallback）。

也可以本地跑一遍接口自测，指到线上地址：

```powershell
$env:BASE='https://<你的服务名>.onrender.com'; node server/scripts/smoke.js
```

⚠️ 注意：这个脚本会真的往线上库写测试数据（一个「测试员xxxxxx」账号、改一条酒店价格再改回来、增删一条目的地/景点/车费）。不想污染线上就别跑，或者跑完用 admin 端把它们删掉。

### 第 6 步 免费实例会休眠（朋友第一次打开慢是这个原因）

- Render 免费 Web 服务 **15 分钟没有请求就休眠**，被叫醒时**第一次请求约 50 秒**（页面一直转圈，等着就行）。
- 之后有人访问的 15 分钟内都是快的。
- 想彻底避免：升级付费实例（$7/月起），或用 UptimeRobot 之类的免费服务每 10 分钟 ping 一次 `/api/health` 保活（不在本项目范围内，属于可选）。
- 数据库侧：TiDB Serverless 空闲也会休眠，但被唤醒比 Render 快；本项目连接池会自动重连，**不需要**重启服务。

## 常见报错怎么查（按现象对号入座）

| 现象 | 原因 / 怎么办 |
| --- | --- |
| Render 构建失败，日志里 `vite: not found` | 打包时没装 devDependencies。根目录 `build` 脚本已带 `--include=dev`；若你手改过，改成 `npm --prefix web ci --include=dev && npm --prefix web run build` |
| 构建失败，日志里 `npm ci can only install with an existing package-lock.json` | `web/package-lock.json` 没推到仓库。本地 `cd web && npm install` 生成后再 `git add web/package-lock.json` 并推送 |
| 服务一起就退出，日志「启动失败：缺少必需的环境变量」 | 缺 `DB_HOST`/`DB_USER`/`DB_NAME`/`JWT_SECRET` 之一。Render → Environment 里补上（本地则复制 `server/.env.example` 成 `server/.env`）。程序会逐条列出缺什么 |
| 打开网址 502 / "Application failed to respond" | 服务没起来。看 Render **Logs** 最后 30 行；常见是环境变量写错、端口被写死（不要设 `PORT`） |
| 页面白屏，控制台 404 一堆 `/assets/xxx.js` | 前端没打包成功，`web/dist` 不存在。看构建日志有没有 `✓ built in`；也可以 `/api/health` 是否正常来判断后端 OK |
| 接口返回 `{"error":"连不上数据库，请检查 .env / Render 环境变量里的 ..."}` | `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD` 有错。TiDB 的 Host 不带协议前缀，端口是 4000 |
| 接口返回 `{"error":"数据库还没建好，先跑 npm run db:setup ..."}` | 表不存在 → 第 3 步没做或做在了别的库上 |
| 日志/接口出现 `HANDSHAKE_SSL_ERROR`、`certificate`、`self signed` | TLS 相关：确认 `DB_SSL=true`；仍报证书错误就把 `DB_SSL_REJECT_UNAUTHORIZED` 设 `false` 再试 |
| `ER_ACCESS_DENIED_ERROR` / Error 1045 | 用户名或密码不对。TiDB 用户名带 `.root` 后缀，别漏；密码只在生成那一刻可见，丢了重新 Generate |
| `ER_DBACCESS_DENIED_ERROR` | 账号没权限访问该库：确认 `DB_NAME` 拼写，或在 TiDB SQL Editor 里先 `CREATE DATABASE travel_cost;` |
| 中文变成 `????` | 一般不会：三张表都是 `utf8mb4`，连接也强制 `utf8mb4`。若用 Navicat 手动导 SQL，注意导出的文件编码存成 UTF-8 |
| 第一次打开要等 50 秒 | 免费实例休眠，**正常现象**，见第 6 步 |
| 登录后过一会儿又要登录 | `JWT_SECRET` 每次部署都变（没设的话）。设成固定值就稳定 |

### 复查用的小命令

```powershell
node server/scripts/db-config.js          # 看当前生效的数据库连接（密码打码；本地/云上都适用）
node server/scripts/smoke.js              # 接口自测 52 项（默认打 http://localhost:3000）
$env:BASE='http://192.168.1.11:8080'; node server/scripts/smoke.js   # 换成任意地址
```

`DB_SSL=true node server/scripts/db-config.js` 会打印出真正交给 mysql2 的 `ssl` 配置，用来确认「云库 TLS 确实开了」。
